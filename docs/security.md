# Security

## HTTP headers

Set globally in `next.config.ts` `headers()`: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, a restrictive `Permissions-Policy`, and a `Content-Security-Policy` that allows only `self` plus the specific third parties required (Google Tag Manager script, Google Analytics connect). Update the CSP if new third-party scripts are added — do not broaden it to `unsafe-eval` or wildcard sources.

Traefik adds HSTS and additional secure-header middleware at the edge (see `docker-compose.yml` labels) — headers are intentionally set at both layers so the app is still safe if it's ever run behind a different proxy.

## Form handling

- All three forms (tour, leasing, general) validate with Zod **on the server** inside `src/app/actions/leads.ts`, not just client-side via React Hook Form — client validation is a UX layer, never the security boundary.
- Every form includes a honeypot field (`honeypot`, must stay empty; visually hidden, `tabIndex={-1}`) — a filled honeypot is silently accepted without sending anything, to avoid tipping off bots.
- `isRateLimited()` (`src/lib/rate-limit.ts`) caps submissions to 5 per minute per IP, in-memory. This is sufficient for a single-instance deployment; if the app is ever scaled to multiple replicas, replace it with a shared store (Redis) — see the comment in that file.
- No sensitive values (email, phone, message content) are ever passed to `track()` — enforced by a strip-list in `src/lib/analytics.ts`.
- Server logs never print raw email addresses (`LogMailAdapter` redacts them) — see `src/lib/mail/adapter.ts`.

## Environment / secrets

- All environment variables are validated at startup via `src/env.ts` (Zod) — the app fails fast with a clear error if misconfigured, rather than silently running with missing config.
- Only variables genuinely safe for the browser are prefixed `NEXT_PUBLIC_*` (site URL, GTM ID, a domain-restricted Maps **Embed** key). `LEADS_WEBHOOK_URL` and any future server secrets are never exposed to the client bundle.
- `.env.example` documents every variable; real `.env`/`.env.local` files are gitignored and must never be committed.

## Dependency hygiene

Run before each release:

```bash
npm audit
npm outdated
```

Address any high/critical advisories before deploying. Pin dependency versions via the committed `package-lock.json` (already generated by `npm ci` in the Docker build, ensuring deterministic installs).

## Uploads

No file upload functionality exists in this build. If one is added later (e.g. brochure upload in an admin flow), it must: restrict accepted MIME types and extensions, enforce a maximum file size, store files outside the web root or in object storage with generated filenames (never trust the client-supplied filename, to prevent path traversal), and be scanned or otherwise validated before being served publicly.

## Container security

- Multi-stage Docker build (`Dockerfile`) — the production image contains no dev dependencies, no source maps beyond what Next.js ships by default, and no build tooling.
- Runs as a non-root user (`nextjs`, uid 1001) — see `Dockerfile`.
- `npm ci` is used (not `npm install`) for deterministic, lockfile-driven installs.
- Health check endpoint (`/api/health`) returns only a status and timestamp — no internal diagnostic information.
- Port 3000 is not published directly in the production `docker-compose.yml`; only Traefik routes to it over the internal Docker network.
